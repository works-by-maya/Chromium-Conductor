# Chromium Conductor v1.1.0

This release updates Chromium Conductor's Apple silicon build to **Chromium
154.0.8037.57** and adds a downloadable macOS disk image. The existing native
per-tab Core Audio routing is retained, with its patches refreshed for Chromium
154.

Based on ungoogled-chromium-macos **154.0.8037.57-1.1**. Conductor's project
version, `v1.1.0`, is separate from the Chromium and upstream package versions.

## Highlights

- **Downloadable ARM64 app:** a compressed disk image containing `Chromium.app`
  and an Applications shortcut for drag-and-drop installation.
- **Verified packaging:** image integrity, packaged app contents, executable
  permissions, framework symlinks, and the Applications shortcut are checked
  before the image is saved. A SHA-256 checksum accompanies the download.
- **Package an existing build:** `./conductor.sh --package` creates release
  assets without rebuilding Chromium or downloading build dependencies.
- **Chromium 154 compatibility:** the audio-routing patches and build tooling
  have been updated for this upstream release. The ARM64 ThinLTO build profile
  is preserved.

## Download and Install

Download both release assets:

- `Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg`
- `Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg.sha256`

From the folder containing both downloads, verify the image:

```bash
shasum -a 256 -c Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg.sha256
```

The command should report `OK`. Open the disk image, drag `Chromium.app` to
Applications, eject the image, and launch Chromium from Applications. The app
continues to be named **Chromium**.

**Platform:** Apple silicon (ARM64) only. The app declares a minimum macOS
version of **13.0**; compatibility across all supported macOS versions has not
been tested. No Intel build is provided.

**Signing:** this download is **not Developer ID signed or notarized by Apple**.
macOS may block the first launch. If you choose to open it, follow
[Apple's instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

ChromeDriver was built successfully but is not included in the disk image or
attached as a separate download in this release.

## Build Fixes

- Support upstream's Python resource helper while retaining compatibility with
  older releases that use the shell helper.
- Retrieve Chromium through upstream's release-pinned clone workflow, avoiding
  the missing source archive that prevented this version from building.
- Check Python 3.10–3.13, required Python modules, and Go before clearing
  generated build state.
- Select an installed macOS SDK that passes the downloaded LLVM linker's
  compatibility check, and use that SDK consistently for bindgen and Chromium.
- Keep GN's SDK link inside the build output directory and correct bindgen's
  lookup of its bundled `libclang`.
- Use checkout-local TypeScript and version-matched, integrity-checked esbuild
  instead of requiring hard-coded Homebrew executables.
- Reuse the Ninja output cache only when rebuilding the same upstream release.

See the [README](https://github.com/works-by-maya/Chromium-Conductor#readme) for
the updated source-build prerequisites and packaging instructions.

## Validation

- The full ARM64 build of Chromium and ChromeDriver completed successfully.
- Conductor's source/build verification passed.
- The disk image passed its internal integrity check and a read-only comparison
  of the packaged app against the completed build.
- The SHA-256 checksum was independently checked. Packaging failure checks
  covered version mismatches, missing apps, existing release assets, and cleanup
  after an interrupted attachment.

These checks cover compilation and packaging; they do not establish a complete
browser or audio-device compatibility test matrix.
