# Chromium Conductor v1.1.0

Well, that took some wrangling. :D

Conductor is now on **Chromium 154.0.8037.57**, and this release comes with a
Mac disk image. You can download the app, open the image, and drag Chromium
into Applications.

I started this project because I wanted to send a browser tab's audio straight
to the stereo through Core Audio. That's still what Conductor is here for.
The **Send Audio To** menu and native per-tab routing are carried forward in
this update, with the patches refreshed for Chromium 154.

This is still my Apple silicon-only build, with ARM64 and ThinLTO optimizations.
It's based on ungoogled-chromium-macos **154.0.8037.57-1.1**. **v1.1.0** is
Conductor's version; the Chromium and upstream package versions have their own
numbering.

## A disk image. Finally. :D

The download includes `Chromium.app` and an Applications shortcut for
drag-and-drop installation. The app is still named **Chromium** on your Mac.

I also added `./conductor.sh --package`, so an existing build can be packaged
without compiling Chromium again or downloading build dependencies. The
packager checks the image, app contents, permissions, framework links, and
Applications shortcut before saving it, and writes a SHA-256 checksum alongside
the image.

## Getting it onto your Mac

Download both files:

- `Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg`
- `Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg.sha256`

From the folder containing the downloads, check the image:

```bash
shasum -a 256 -c Chromium-Conductor_154.0.8037.57-1.1_macos-arm64.dmg.sha256
```

You should see `OK`. Open the disk image, drag `Chromium.app` into Applications,
eject the image, and launch Chromium from Applications.

This download is for **Apple silicon (ARM64)**. There's no Intel build. The app
specifies **macOS 13.0** as its minimum version, but I haven't tested it across
every supported macOS version.

This download is **not yet Developer ID signed or notarized by Apple**, so macOS
may block the first launch. If you choose to open it, follow
[Apple's instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

ChromeDriver built successfully too, but it isn't included in the disk image or
offered as a separate download in this release.

## The build needed some love, too

Getting Chromium 154 built involved a few detours. Those fixes are now part of
Conductor:

- Source retrieval uses upstream's release-pinned clone workflow, fixing the
  missing source archive that stopped the build. The script supports upstream's
  Python resource helper and the older shell helper.
- Python 3.10–3.13, its required modules, and Go are checked before generated
  build files are cleared.
- SDK selection checks compatibility with the downloaded LLVM linker, then
  uses the same SDK for bindgen and Chromium. GN's SDK link stays inside the
  build output directory, and bindgen can find its bundled `libclang`.
- DevTools uses TypeScript from the checkout and a matching, integrity-checked
  esbuild download. The hard-coded Homebrew executable paths are gone.
- Ninja output is reused only when rebuilding the same upstream release.

The [README](https://github.com/works-by-maya/Chromium-Conductor#readme) has the
updated build requirements and packaging instructions if you'd like to build
it yourself.

## What I checked

Chromium and ChromeDriver completed the full ARM64 build, and Conductor's
source and build verification passed. The disk image passed its integrity
check, the packaged app matched the completed build, and the SHA-256 checksum
was independently checked. I also checked that packaging handles version
mismatches, missing apps, existing release files, and cleanup after an
interrupted image attachment.

I also checked all **16 native binaries** in the browser, helpers, and libraries
for debugging symbols. Neither the built app nor the copy in the disk image
contains embedded debug information or debug symbol files such as `.dSYM`
bundles.

These checks cover the build and packaging. I haven't tested every browser
workflow or every combination of audio devices.
